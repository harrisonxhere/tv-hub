# 视图清单与坐标

> 坐标系：1280×720 设计舞台，左上角原点。所有数值单位是 dp（= 设计稿像素）。
> 内容区左右各留 64dp、上下各 30dp，所以内容宽恒为 **1152dp**、高恒为 **660dp**。

---

## 间距规范（全局）

纵向坐标全部落在 4dp 栅格上，只有四条规则。层级靠间距大小区分：
**同一区块内部 < 标题与内容 < 区块之间**。

| 关系 | 值 | 首页示例 |
|---|---|---|
| 导航 → 首屏内容 | **20** | TopBar 底 52 → 主推卡顶 72 |
| 区块 → 区块 | **24** | 主推卡底 416 → 「最近更新」标题顶 440 |
| 标题 → 内容 | **16** | 标题框底 464 → 卡片行顶 480 |
| 卡片之间（横向） | **20** | 5 张横幅卡 `spacedBy(20)` |
| 紧凑列表行距 | **6** | 右侧热门 4 行，行高 72、步进 78 |

- 标题框统一高 24dp（18sp 主标行高 23.4，副标 11.5sp `padding(bottom = 2)`，两者底对齐）。
- 区块标题统一结构：粗体 18sp 主标 + 11px 间距 + 11.5sp `C.Fg3` 副标（首页各分栏、分类/房间页的 `VHead` 同构）。
- 静态页面（分类 / 房间 / 我的 / 设置）内容底落在 660，视觉上距屏幕下沿 30dp，与顶部 30+4=34 近似对称。
  **首页是可滚动的**：视口固定 72..660，内容超出后纵向滚动，底部 24dp 渐隐收口。

## 详情页两栏的基线

右栏（400dp）里的**文字内容统一从 10dp 起排**，卡片类容器（安装按钮、签名校验卡、横幅预览）仍占满宽：

- 事实区（体积 / 更新 / 版本 / 许可证）的顶部分隔线与两行 `Fact` 都加 `horizontal = 10.dp`。
- 「同房间 · …」标题行加 `horizontal = 10.dp`；`MoreRow` 的行内容本身也有 10dp 内边距，这样标题、列表项、数量文字才对得齐。
- `MoreRow` 的行分隔线同样内缩 10dp，否则线会比内容两头各长出一截。

**纵向**：两栏的 header 区都锁进 `DETAIL_HEAD = 384.dp` 的固定高度里，所以左栏「横幅预览」和右栏「同房间」从同一条 y 起，顶部齐平。

- 之前右栏是用 `Spacer(Modifier.weight(1f))` 把推荐区推到底部，结果和横幅底部对齐、顶部差 20 多 dp。
- 384 是给「简介两行 + 四条时间线」留的余量，两栏自然高度都小于它，多出来的就是留白；
  改这页的间距时要同步复核这个值，否则右栏内容会被裁或压到横幅上。
- 拉对齐时别只比文字墨迹：`10.5sp` 的标题行自带约 2dp 上留白，量像素时差 3–4px 属正常。
- **底部也要齐平**：推荐区是 `weight(1f)` + `Arrangement.SpaceBetween` —— 标题贴顶、列表贴底，
  于是同时跟横幅的上下两端对齐，多出的高度落在标题与首行之间（26 → 约 32dp）。
  注意 `more.forEach` 必须包一层 `Column`，不然 SpaceBetween 会把每一行甩到分隔位置上。

## 应用卡片的圆角与比例

应用卡的底色沿用原来的取色逻辑，**不许换成白底**：

- 有横幅：`edgeColors(bmp)` 取左右两端主色，横向渐变铺底。
- 没有横幅（`NameCard`）：`iconHue()` 按「饱和度 × 明度」加权求图标主色相，铺同色系渐变 + 图标背后一层柔光；
  确实无图标才把应用名排进去（深色主题白字、浅色主题 `C.Fg`），加载中只留渐变底。

这次只调**圆角与长宽比**（参考 Google Play 的电视卡片：201×114 ≈ 1.76:1，圆角约短边 25%）：

- 圆角统一走 `tileRadius(shortSide)`：`短边 × 25%`，夹在 8–28dp，免得大横幅被圆成胶囊；
  `tileShape(shortSide)` 由它构造。**聚焦环的 `ring(f, radius, …)` 必须传同一个 `tileRadius(…)`**，
  否则环还是小圆角、卡是大圆角，选中时会明显对不上。
- 「最近更新」和分类货架行（`ShelfRow`）行高 148dp，5 张卡各约 214×122dp，比例贴近 16:9；之前 128dp 时偏扁（2.1:1）。
- 本周热门缩略图 104×58、详情页 168×94、推荐行 64×36、房间网格 `aspectRatio(16f/9f)` 本来就是 16:9，只改圆角。
- 分类房间磁贴 `RoomTile` 不是应用卡，保持原来的深色氛围底图。

## 图标规范（图片呈现）

同一屏里的图标必须"看起来一样大"，靠三个函数兜住（都在 `Screens.kt`）：

| 函数 | 做什么 | 为什么 |
|---|---|---|
| `trimIcon(bmp)` | 先裁掉源图自带的外圈留白：外圈一半以上透明就按 alpha 裁，否则按"外圈平均色"的色差裁 | 自适应图标把前景缩在 192 画布中间、白底图标自带白边，不裁就会「有的大有的小」 |
| `FitIcon(bmp, box, fill)` | 裁完再按**面积**归一摆进方框，而不是长边 Fit | 2:1 的横版 wordmark 用 Fit 只剩一半高度，同排看着明显偏小 |
| `blankArt(bmp)` | 8×8 采样亮度极差 < 8 判为纯色占位图，当"没有图" | SkyTube 的 `banner_default.png` 就是纯 #222，直接用会得到一张死黑卡 |

**没有图标时不用任何通用符号**：卡片（`NameCard`）里直接把应用名当主视觉排进去，
列表行（`AppIcon` / 本地应用行）**留空**——名字就在右边，塞个占位符只会像加载失败。

名字的字号由 `nameFontSize(name, w, h, maxLines)` 算，不再是固定比例：

1. 起点 `min(宽 × 0.20, 高 × 0.46, 36sp)`，让短名（`Home`、`Piik`）撑满卡片；
2. 从起点每次 −0.5sp 往下试，直到同时满足三条：折行数 ≤ `maxLines`、
   `最长单词` 单行放得下（否则会被吃掉省略号）、总行高 ≤ `高 × 0.78`；
3. 折行数与字符宽度都按 `0.60em` 估算，CJK 按 2 个拉丁字符宽计。

字号地板 8sp、封顶 36sp；`maxLines` 是「卡片高 < 48dp 给 2 行，否则 3 行」。
177×100 的海报卡上 `Piik` 约 35sp，104×58 的热门缩略图约 20sp，
600×180 的详情预览区 36sp——都比旧的 `宽 × 0.068`（海报卡只有 12sp）大一倍以上。

> **图片是三态的，别把「加载中」当成「没有图」**：`url == null || Images.knownBad(url)` 才算没有图，
> 其余情况在 `bmp == null` 时只铺渐变底、什么都不画，等图到位再 180ms 淡入。
> 否则卡片会先闪一版应用名、再跳成图标（这是 2026-11-19 修过的真实 bug）。
> `Images.knownBad` 变化时 `Images.epoch` 会 +1，`remember` 拿它当 key 才能及时重算。

- `trimIcon` 至少削掉 6% 才生效；削完不足原图 20% 视为误判，放弃裁剪。
- `trimIcon` 的包围盒按 `step` 抽样（长边 >160 取 2），480 宽的横幅从 13 万次判读降到 3 万次，
  主线程不会因为一批缩略图卡住；抽样会漏最外一圈，所以四个边界各补回一个步长。
- `FitIcon` 的 `fill`：横幅卡 / 图标卡 **0.94**，列表行 34dp **0.86**，本地应用行 30dp **0.84**。
- 小缩略图（热门 104×58、同房间 64×36）同样先 `trimIcon` 再铺，否则内置 logo 小到看不清。
- 卡片在没有横幅时一律走 `NameCard`，不再画深色空块。

### 图片预热（`Warm`，`Data.kt`）

慢的从来不是渲染，是网络：一张 GitHub raw 的图经 `gh-proxy` 单次要 300–800ms，进一个分类页
要同时取十几张，于是有 2–4 秒的空白。`Warm.start()` 在目录读完后（`TvHub` 的 `LaunchedEffect`）
把首屏的图**先下到磁盘**，UI 真正要显示时只差一次本地解码。

| 约束 | 取值 | 理由 |
|---|---|---|
| 队列顺序 | 主推位 → 首页热门/最近 → 各分类首屏 | 越可能先看到的越靠前 |
| 分类分批 | 先每类首行 6 张，再回头补后 12 张 | 按分类整块下，排最后的分类要等好几分钟 |
| 通道数 | 5 | 单张 1–3 秒，3 条太慢；再多靠让路兜底 |
| 让路 | `Images.busy > 0` 时暂停（每 260ms 复查） | 用户正在等当前这一屏，别抢带宽和连接数 |
| 预算 | 单次启动 48 MB | 超了就停，剩下的等真要用时再取 |
| 超时 | 连接 4s / 读 8s（UI 仍是 10s / 20s） | catalog 里总有取不到的图，别让坏 URL 堵住通道 |

- 预热**只落盘不解码**（`Images.warm`）：解码后的位图留在 LRU 里会挤掉用户正在看的这一屏，
  而本地解码本身只要几十毫秒。
- 预热失败**不标** `Images.knownBad`：预热失败多半是临时抖动，标了会把图永久降级成文字。
- 磁盘缓存按 URL 哈希，与解码宽度无关，所以队列只按 URL 去重，一张图只下一次。

实测（模拟器，清空 `cache/img` 后）：Steaming 分类进入 1 秒时 17/18 张就位（改前只有 4 张），
VPN & network 与 Other（队列最后一组）1 秒内 18/15 张全出图。

## 0. 外壳

### `TvHub()` 根

```kotlin
Box(Modifier.fillMaxSize().padding(horizontal = 64.dp, vertical = 30.dp)) {
    Panel(Modifier.fillMaxSize()) { /* 顶栏 + 当前视图 + ToastHost */ }
}
```

`Panel` 在 v8 之后**只是空 Box**（用户要求「不要最外面的圆角边框，直接就是背景」），
圆角 / 描边 / 投影全部移除，内容直接坐在 `Wall` 色雾背景上。

`Wall(tints)`：全屏三团径向渐变 + 顶部压暗，颜色来自首页前三张卡片的提纯主色。

### `TopBar`

位置 `at(0, 4) · 1152×48`（距屏幕上沿 34dp，与子页「‹ 返回」胶囊的 30dp 基本对齐），左对齐单行：

| 区 | 内容 |
|---|---|
| 左 | `Brand(36.dp)`（彩色徽标，**不走 tint**）+ 10dp + 「OpenAPK TV」17sp Bold（BETA 已移除） |
| 中 | 胶囊导航：44dp 高、`CircleShape`、`Line` 描边、内边距 4dp；发现 / 分类 / 我的应用 三项**等宽**、36dp 高 |
| 右 | 搜索按钮（40×40）+ `weight(1f)` + 齿轮（40×40），聚焦反色 |

`NavItem` 的三种状态（缺一不可，尤其是浅色主题）：

| 状态 | 底 | 字 |
|---|---|---|
| 静息未选中 | 透明 | 13sp Medium `C.Fg3` |
| **选中**（当前标签页） | `C.Fg` 半透明实心：深色主题 30%、浅色主题 22%，`CircleShape`，**不描边** | 13sp **SemiBold** `C.Fg` |
| 聚焦 | `C.HiBg` 反色实心（不加外扩焦点环；`HiBg` 自带 12% 透明度，不是死白/死黑） | 13sp SemiBold `C.HiFg` |

选中色必须用 `C.Fg.copy(alpha=…)`，**不能写死 `0x21FFFFFF`**：白色半透明在浅色主题下叠在浅底上等于没有选中态。
选中态的透明度按「比静息高一档、又明显低于聚焦反色」定；18% 在深色主题里几乎看不出来，现在深色 30%／浅色 22%，且不再加 1dp 描边——描边会让选中胶囊在小尺寸下显脏。
选中（浅灰实心）与聚焦（反色实心）是两种不同表达，可以同时出现在相邻两项上，互不混淆。

**三项等宽（不能改成 `weight(1f)`）**：胶囊本身是 wrap-content，直接给 `weight(1f)` 会把顶栏剩下的整段空白都吃进来。
做法是先量文字：`rememberTextMeasurer()` 按 13sp / SemiBold 量三个标签（`我的应用` 最长），取最宽的一个 + 左右各 18dp 作为**三项共用的固定 width**，
文字在等分格里居中。这样选中/聚焦块永远落在同一份宽度里、左右留白对称；量出来的宽度跟着语言走，英文长标签也不会被裁。

反色底 `C.HiBg` 带 12% 透明度（深色主题 `0xE0FFFFFF`、浅色主题 `0xE0101620`）：纯白/纯黑在 TV 上像块补光灯，
透一点让背景色雾（`Wall`）微微透出来，整屏更整体。**文字/图标仍用实心 `C.HiFg`**，把透明度加在前景上会掉对比度。

**导航项不用 `ring()`**：外框只有 44dp、内边距 4dp，而 ring 的外扩（2 gap + 2 线 + 7 光晕，另加 1.06 放大）必然被父级 `clip(CircleShape)` 削平，并压到相邻胶囊上（会看到切掉的白弧和月牙）。聚焦改为「反色实心胶囊」，边缘完整落在 gutter 内。

- `deep == true`（详情页）时导航与齿轮不响应，`canFocus = false`。
- 顶栏用 `navReq: Map<Tab, FocusRequester>`；内容区用 `handoff.target`。**两套不能混。**

### 通用页头 `VHead(title, sub, hintKey, hint, y)`

位置 `at(0, y) · 1152×42`：左边 20sp 大标题 + 11.5sp 副标题；右边一个按键提示胶囊（只用 `OK` + 说明文字）。
**不写 `ESC 返回`**：返回统一靠左上「‹ 返回」胶囊，键盘 ESC 静默生效、不上屏。

## 1. 发现（首页）`HomeScreen`

首页是**可纵向滚动**的分栏货架：TopBar 固定，正文从 72 起占 588 高滚动视口。

```
(0,4)    1152×48    TopBar（固定，不随正文滚动）
(0,72)   1152×588   LazyColumn 视口，项间距 24，contentPadding 顶 12 / 底 40
   ├ 主推区 1152×344   轮播 648×344 + 右侧「本周热门」484
   ├ 最近更新 1152×168 标题 24 + 16 + 卡行 128（5 张，间距 20）
   └ 每个一级分类一栏 ×13  标题 24 + 16 + 卡行 128（首位「全部」128 + 4 应用 236）
(0,636)  1152×24    底部渐隐（Wall 基色，透明 → 实色）
```

右侧热门：标题框 24 高，行 `y = 38 + i*78`、高 72（缩略 104×58 + 上下各 7），
末行 272..344 与主推卡底边齐平。

**分栏 `ShelfRow`**：**分组口径与「分类」页完全一致** —— 按键是 `group`（不是上游 `room`），
集合与顺序照抄 `GROUP_KEYS`，`GROUP_OTHER`（其它）永远最后；栏标题 `groupName(group)`，
名字和先后与分类页磁贴逐个相同。副标只说「精选了几款」（`shelf_sub`，N 款 = 卡行里实际给出的应用数），
**总数交给首位那张卡**，两边不重复报同一个数。
正文 = 首位 `ViewAllCard`（固定 128dp）+ 4 张 `WideCard`（等分 236dp），间距 20；
应用不足 4 个时在尾部塞 `Spacer` 占位，应用卡宽度不随数量变化。

**「全部」`ViewAllCard`**：放在**最前面**而不是末位——遥控器从左往右走，先经过入口再到精选，
一进这一行就能看到「这一栏一共有多少款」；它也比应用卡**窄一截**（128 vs 236），
在节奏上属于「入口」而不是「内容」，宽度差一眼就能把两者分开。
不铺图，用**本栏主色**做斜向渐变（`lerp` 混合底色：深色主题 `#1A1F28` 62%→26%，
浅色主题 `#F5F7FB` 34%→14%，保证卡片边缘始终是实体、不会在右下角化进背景），
卡面居中两行：10.5sp 弱化的「全部」（`shelf_all`）+ 30sp 粗体总数（`Fmt.count`，带千分位）。
卡下不写标题（文字已在卡里），只留 24dp 空档让卡底与邻卡封面底边齐平。
聚焦整体反色成 `C.HiBg` / `C.HiFg`。
点开的是分类页磁贴进去的同一个页面（`RoomScreen` 同样按 `group` 取数）。
总数口径 = 当前可见池里的 `group` 计数（关掉「隐藏串流」会实时变少），与栏内精选 4 款同源。
别改回「按 `room` 分组 / 按数量降序」：那会让首页出现 18 栏、名字对不上磁贴（Streaming vs 影视），用户记不住位置。

**滚动与焦点**：
- 焦点换到某一行时 `animateScrollToItem(行号)` 把整行对齐视口顶部，避免 LazyColumn 自带的
  `bringIntoView` 只保证被聚焦那张卡可见、把栏标题顶出画面。行号：0 主推、1 最近更新、2+i 第 i 栏。
- `homeMemo` / `homeRow` 记住首页最后聚焦的应用（或 `all:<group>`）和行号；返回首页时先
  `scrollToItem(homeRow)` 再抢焦点，否则主推卡早被 LazyColumn 回收，直接请求 `heroReq` 会失败、整页无焦点。
- 主推位用独立的 `heroReq`，`handoff.target` 专供「上次聚焦的那张卡」，两者不能混挂。

**主推 `HeroCarousel`**：外层 `Focusable` 是唯一焦点节点（焦点环 / 阴影 / 裁剪共用 `tileShape(344.dp)`，钳到 28dp，与下方卡片同一套圆角；聚焦放大 1.007）。**裁切与压暗挂在同一层**：`clip` + `drawWithContent`（压暗渐变 + 卡底 2px 近黑兜底 + 底段 1px 内收边），文字与指示点画在 card 之上，见 DESIGN-SYSTEM 5.1c；
**不描边**（卡底近黑，1dp 的 `C.Line` 会在那里单独亮成一条线），边界靠图 + 压暗 + 聚焦环（见 DESIGN-SYSTEM 5.1c）；
内层 `Crossfade`(550ms) 只换 `HeroContent`，`HeroDots` 放外层不跟着闪。
`HeroContent`：`edgeColors` 渐变 + `art(url, 32)` 糊底铺满（补掉 Fit 的留白，见 DESIGN-SYSTEM 5.1b）→ 按比例算出 contain 矩形、`FillBounds` 画图 + 12dp 内距 + 四边 8% 羽化 → 上下压暗（向下多铺 2dp，卡底不留未压暗的行，见 5.1c）→ 左下 36sp 名称 + 13sp 卖点（底距 26），右端留 142 给指示点。
7 秒自动切换；不在发现页 / 有子页 / 焦点落在大卡上时暂停。

`SetRow`：左标题 13sp + 副标题 10.5sp，右侧 `control: @Composable (focused: Boolean) -> Unit`。
**control 必须用 `focused` 切前景色**（`fg = if (it) C.HiFg else C.Fg`），否则浅色主题下整行反白时看不见。

`Seg` 是纯展示件（「外观主题」与「下载源」两处）：遥控器只有一个确定键，所以 `onClick` 是
「循环切下一档」，不是点选某一段。下载源三档循环：自动 → GitHub → 国内镜像。

**下载源的副标题必须写「当前实际走哪条」**：自动档的结果取决于系统语言，只写「自动」用户不知道
现在到底有没有走镜像。三档分别显示 `自动 · 当前走国内镜像` / `始终直连 GitHub，不经代理` /
`始终走国内镜像，失败回退 GitHub`（判断逻辑见 `ARCHITECTURE.md` 2.4）。

**语言选择 `LangPickerDialog`**（界面语言行按 OK 打开）：
- 用 `Dialog`（`usePlatformDefaultWidth = false`）而不是页面内浮层：独立窗口天然把焦点关在弹层里，
  返回键由系统转成 `onDismissRequest`，不需要手写焦点陷阱。弹层不继承 1280×720 的设计坐标系，
  内部按窗口尺寸重算一次 `LocalDensity`，保证字号和 1280 稿一致。
- 结构：全屏 65% 黑遮罩 + 560dp 宽面板（`C.Card`、22 圆角、投影，不描边），标题「界面语言」+
  副标「N 个选项 · 按 OK 切换，返回键取消」，下面是 `LazyColumn`（最多露 7 行，再多就滚动）。
- 行高 52dp，当前语言右侧打勾并加粗；聚焦行**整行反色**（`C.HiBg` / `C.HiFg`），不挂外扩焦点环——
  `LazyColumn` 会裁边，环会被切平。
- 打开时 `FocusRequester` 落到当前语言；关闭后由设置页把焦点还回语言行。

**「改用国内镜像？」询问框 `MirrorAskDialog`**（不做成设置里的入口，只在系统语言变成简中时弹一次）：
- 触发：`Prefs.noteSystemLanguage()` 在 `onCreate` 比对「上次见到的系统语言」，从非简中变成简中、
  且当前没走镜像时置起 `Prefs.askMirror`；用户选「改为国内镜像」写 `source = 2`，选「保持直连」只关窗。
- 一点约束：**必须等 `Catalog.apps` 非空之后再弹**。启动页阶段主窗口还没有焦点，再盖一个 Dialog 窗口
  会让输入事件无处可去，实测直接 ANR（`Input dispatching timed out, no focused window`）。
- 结构：65% 黑遮罩 + 600dp 面板（`C.Card`、22 圆角、投影），标题 20sp + 正文 12.5sp（行高 1.6）+
  11sp 灰注脚，底部两个等宽按钮 46dp（`DarkBtn(dot = false)` + `GhostBtn(height = 46.dp)`）。
  默认焦点在左「改为国内镜像」。

**`Switch`**：按 Android（Material 3）规格自绘，不用 material3 的组件（项目没引该依赖，且控件的配色要跟着行聚焦态走）。
轨道 52×32、圆角 16；滑块关闭 16dp（左内边距 8）、开启 24dp（左 24），尺寸与位移 180ms 过渡。
关闭态 = 透明轨道 + 2dp 描边 + 灰滑块（描边与滑块同色 `C.Fg3`），开启态 = 实心 `C.SwitchOn` 绿轨道 + 白滑块。
聚焦时行底翻成 `HiBg`，关闭态的描边/滑块改用 `C.HiFg` 的半透明，保证白色行底和深色行底都看得见。

## 分类体系：12 个一级组（数据层）

`catalog.json` 里每个应用现在有三个分类字段，**上游标签一律不动**：

| 字段 | 含义 | 谁在用 |
|---|---|---|
| `room` | 上游原始标签（18 个，如 `Streaming`、`VPN & network`） | 详情页「同房间」、二级 chips |
| `group` | 12 个一级分组 key（ASCII，如 `video`、`system`、`other`） | 分类页磁贴 |
| `sub` | 二级 key，默认等于 `room`；影视里迁出的音乐类改成 `Music` | 房间页二级 chips（`SubChip`） |

12 个组：`video` 影视、`photos` 图片、`music` 音乐、`games` 游戏、`reading` 阅读、
`social` 社交、`browser` 浏览、`home` 家居、`desktop` 桌面、`stores` 应用商店、
`ai` AI 工具、`system` 系统，外加 `other` 其它（848 款，不进一级磁贴）。

合并关系：`Streaming`+`Video`→video、`Reading`+`Learning`→reading、`Launchers`+`Screensavers`→desktop、
`Tools`+`Files & downloads`+`VPN & network`→system。2026-11-22 快照起 video 下多一个二级 `Video players`
（88 款本地播放器，显示名走 `room_local_players`），与 `Video` 分开展示。

**重新分配用 `tools/reclassify.py`**，不手改 JSON：

- 原始数据备份在 `data/catalog-source-2026-11-22.json`，脚本只在备份不存在时创建，不覆盖。
- `python tools/reclassify.py` 只出报告，`--write` 才写入。
- 写入后校验规则：按 `id` 对齐逐字段比对，除新增 `group`/`sub` 外**任何字段都不许变**；总数必须仍是 3582。
- 影视→音乐的迁移只在「名称/包名」上判（`com.x.music`、`Name Radio`），描述里提到 music 的不算，
  否则 Jellyfin、mpv-android 这类会被拖进音乐。`radio` 用词边界匹配，避免 `radiokot` 这种包名误判。

### 多语言：显示名只在资源里

数据里存的是 ASCII key（`video`/`photos`/…），**中文、英文一个都不写在 JSON 和 Kotlin 里**：

| 位置 | 内容 | 加语言时要改吗 |
|---|---|---|
| `catalog.json` 的 `group` / `sub` | 稳定 key | 不改 |
| `Data.kt` 的 `groupNames` | key → `R.string.group_*` | 不改 |
| `values/strings.xml`、`values-zh-rCN/strings.xml` | 具体文案 | 只加一套 `values-xx/strings.xml` |

所以以后接日语、繁中，只要复制一份 `values-xx/strings.xml` 翻 13 条（12 组 + 其它），
数据文件、脚本、Kotlin 全都不用动。上游 `room` 的显示名同理走 `roomNames` → `room_*`，
未知标签会原样回退成英文（`roomName()` 的 `?: room`），所以新增上游标签要记得补 `room_*`。

`sub` 目前取自同一套上游词表，所以 chips 的显示名直接用 `roomName(sub)`，没有第二份映射；
哪天 `sub` 细到「上游没有的说法」（例如影视再拆出「直播 / 点播」），再在 `Data.kt` 加
`subNames` → `R.string.sub_*`，chips 那一行换成 `subName(sub)` 即可（`R.string.sub_all` 已经在）。

**界面语言本身也是表驱动的**：`Data.kt` 里的 `Langs.all` 是唯一的语言表，下标 0 固定「跟随系统」，
其余每项是 `Lang(tag, Locale, 母语名)`；`Prefs.lang` 存的就是这个下标，`L.apply()` 按表取 Locale。
加一门语言 = 往表里追加一行 + 放一份 `values-xx/strings.xml`，设置页弹层会自动多一条，UI 不用改。
语言名直接用母语名（简体中文 / English / 日本語…），这样任何界面语言下用户都认得出自己的语言。

现有文案：`group_video` 影视 / Movies & TV、`group_photos` 图片 / Photos、`group_music` 音乐、
`group_games` 游戏、`group_reading` 阅读、`group_social` 社交、`group_browser` 浏览、
`group_home` 家居、`group_desktop` 桌面 / Desktop、`group_stores` 应用商店、`group_ai` AI 工具、
`group_system` 系统、`group_other` 其它 / Other —— 一级磁贴与「其它」通栏卡共用这一个名字。
